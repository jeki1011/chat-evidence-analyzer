# ChatEvidenceAnalyzer（聊天记录证据分析助手）

> ChatEvidenceAnalyzer 是一款专为法律从业者打造的辅助工具，将海量聊天记录截图自动转化为结构化的法律证据分析报告初稿。

---

## 🎯 一、项目能解决什么问题

在诉讼实务中，聊天记录是重要的电子证据，但面临**提取难、时间线混乱、说话人难辨、法律要件割裂、质证风险高**等痛点。

| 痛点 | 人工处理 | 本工具 |
|---|---|---|
| 几十上百张截图，人工抄时间线 | 耗时数小时，易漏易错 | 自动 OCR + 按时序重排 |
| 分不清哪句是谁说的 | 靠头像颜色肉眼分辨 | 按气泡左右位置自动判定 |
| 看不出中间缺了哪几天记录 | 几乎发现不了 | 自动计算间隔，超出阈值即标 `[时间断层]` |
| 对方"撤回了一条消息"被忽略 | 极易漏掉 | 单独检出并列入待复核 |
| 语音、图片、PDF 附件看不见内容 | 无从下手 | 识别为对应类型，登记为"须调取原始载体" |
| 手写清单、截图里的数字看漏 | 常见 | 正则提取金额并回链到原消息 |
| 只盯着对自己有利的话 | 天然倾向 | 强制拆出「对我方不利陈述」一栏 |

本项目把「聊天截图」直接转化为可供律师接着往下做的**阅卷笔录初稿**——
时间线、说话人、金额、自认与矛盾点自动梳理，法律定性留给你。

> **它只做事实层的整理，不做法律判断。**
> 是否构成要约、承诺、违约、自认，以及诉讼策略，全部留给承办律师。

## ✨ 二、主要功能

- **本地 OCR 批量提取**：批量识别截图中的文字、时间戳、转账记录，标注语音、图片、PDF 附件、通话、撤回等消息类型。
- **说话人智能区分**：自动区分「我方」「对方」及系统提示；按气泡左右位置判定，支持 `--reverse` 反转。
- **时间线自动梳理**：还原对话流，自动标注 `[时间断层]`；沿用上一条时间戳的消息以 `≈` 前缀明示。
- **法律要件导向提取**：自动提取款项（定金/付款/欠款/利息）、履行与交付、承诺与保证、催告与期限、违约与争议、自认。
- **立场拆分**：把对方陈述拆成「对己方有利（自认候选）」与「对我方不利（须准备应对）」两栏，避免一边倒。
- **案件脉络重构**：按时序自动拼接事实链草稿，供改写为「经审理查明」体。
- **存疑点与质证分析**：自动排查真实性风险（撤回、时间断层、时间戳缺失）、提示合法性与关联性审查要点、检测逻辑矛盾候选（我方主张遭对方否认）。
- **律师策略初步建议**：按聊天内容触发法条提示（《民法典》定金罚则、法定解除、电子数据证据规则等），结论部分留空待填。
- **转录模式**：没有截图或 OCR 不可用时，直接输入 JSON / TXT 转录文本，照样出报告。
- **结构化导出**：`--json-out` 导出全部消息、断层与提取结果，便于二次加工或入库。

### 明确不做的事

- ❌ 不做真实性/完整性鉴定，不校验截图是否被裁剪、时间戳是否被篡改；
- ❌ 无法还原**撤回消息**内容，只能提示"须调取原始载体"；
- ❌ 无法获取**语音、图片、PDF 附件**的实质内容，只登记为待复核项；
- ❌ 不生成法律定性与诉讼策略结论，只给法条触发提示与填空骨架；
- ❌ 不做任何内容补全或推测——识别不出就是识别不出，一律留空并标注。

## 🛠️ 三、安装方法

### 1. 环境准备

- **Python 3.10+**（Windows / macOS / Linux 均可，无需 GPU、无需联网）
- 无需任何 LLM API Key：本项目采用**本地 OCR（RapidOCR + onnxruntime）**，不调用云端多模态模型

### 2. 克隆项目与安装依赖

```bash
git clone https://github.com/your-username/ChatEvidenceAnalyzer.git
cd ChatEvidenceAnalyzer

python -m venv .venv
# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
```

依赖仅两项：

```
rapidocr-onnxruntime>=1.3.0   # 本地 OCR 引擎，模型随包安装，约 14MB
pillow>=10.0.0                # 仅用于生成示例截图
```

### 3. 配置环境变量

**无需配置。** 本项目不依赖任何云端 API，因此没有 `.env`、没有密钥，也不存在密钥泄露面。

### 4. 验证安装

```bash
python -m chat_evidence --help          # 查看命令帮助
python -m unittest discover -s tests    # 运行单元测试（16 项，应全部通过）
```

## 🚀 四、使用方法

### 方式一：命令行批量处理截图

```bash
python -m chat_evidence report \
  --images ./screenshots \
  --out ./report.md \
  --json-out ./report.json \
  --gap-days 7
```

| 参数 | 说明 |
|---|---|
| `--images` | 聊天截图目录，按文件名**自然排序**（`1.jpg < 2.jpg < 10.jpg`） |
| `--transcript` | 人工转录文件（`.json` 或 `.txt`），无截图时使用 |
| `--out` | 输出 Markdown 报告路径（必填） |
| `--json-out` | 同时导出结构化 JSON |
| `--gap-days N` | 时间断层阈值（天），默认 `7` |
| `--reverse` | **截图取自对方手机时**必须加，反转左右说话人 |

> ⚠️ 说话人判定依赖"右侧＝我方（持机人）"这一前提。
> 若截图来自对方手机或对方提供的录屏，**必须加 `--reverse`**，否则整份报告说话人完全颠倒。

### 方式二：无截图的转录文本模式

OCR 不可用、或你已人工整理过对话时：

```bash
python -m chat_evidence report --transcript ./transcript.json --out ./report.md
```

JSON 格式：

```json
[
  {"date": "2026-01-05", "time": "10:20", "speaker": "对方", "content": "李姐，房子我3月1号就退租了，押金1万2什么时候退？"},
  {"date": "2026-01-05", "time": "10:25", "speaker": "我方", "content": "墙面有损坏，我要扣3000维修费。"}
]
```

TXT 格式（每条一行）：

```
2026-01-05 10:20 对方 | 李姐，房子我3月1号就退租了，押金1万2什么时候退？
```

### 方式三：只做 OCR，导出带坐标的文本行

```bash
python -m chat_evidence ocr --images ./screenshots --out ./lines.json
```

### 方式四：分析范式作为提示词复用

本报告的结构（一、案件概况 → 二、时间线 → 三、关键信息 → 四、脉络重构 → 五、存疑点与质证风险 → 六、策略建议）
本身即是一套可复用的分析范式，可复制到 Coze、Dify 等平台作为 Agent 提示词使用；
规则词典位于 `chat_evidence/config.py` 的 `ELEMENT_RULES`，可按业务领域自行扩展。

**三、案件关键信息提取**（金额回链原消息；自认与不利陈述分列）：

```markdown
- **涉及金额（自动提取，须与支付凭证核对）**：
  - 第1条（2025年3月10日，对方）：`5万`　语境：李哥，最近资金周转不开，能不能借我5万应急？
  - 第5条（≈2025年3月10日，我方）：`50000元`　语境：已转账50000元，你查收一下。
- **对方陈述中对己方有利的内容（自认候选，须复核）**：
  - 第3条（≈2025年3月10日）：没问题，我给你打借条，利息按银行同期利率算。
```

**五、存疑点与质证风险提示**：

```markdown
### 1. 真实性风险（自动检测）
- 检出 1 条撤回消息，内容无法从截图还原 → 须调取原始载体核查撤回内容
- 检出 3 处时间断层：2025-03-10 → 2025-06-12（间隔 94.0 天）

### 4. 逻辑矛盾点（自动检测候选）
- **主张未被对方确认**：我方第13条「不行，你必须按约定还。」
  ↔ 对方第14条「那我没办法，你爱起诉就起诉吧」
```

**六、律师初步策略建议**（法条触发提示自动生成，结论留空待填）：

```markdown
- 检出催告表述 → 可结合《民法典》第 563 条第 1 款第（三）项（迟延履行经催告）审查。
- **请求权/抗辩路径**：［待人工填写］
- **不利点与软肋**：［结合第三部分「对我方不利陈述」填写，不得回避］
```

## ⚠️ 八、已知限制

1. **OCR 准确率依赖截图清晰度**，模糊、反光、压缩严重的截图会漏识，输出前必须人工核对。
2. **说话人判定基于气泡左右位置**，群聊、引用消息、合并转发、系统卡片等特殊排版可能判错。
3. **时间精度受限于微信机制**：微信只在间隔较大时插入时间戳，大量消息只能沿用前一时间戳（`≈`）。
4. **不读取实质内容**：语音、图片、PDF、撤回消息只登记类型与位置。
5. **关键词库为通用词典**，命中仅代表"需要重点看"，不等于法律定性。
6. **水印、EXIF、时间戳真伪**不在本工具能力范围内，需另行申请电子数据鉴定。

## 🔒 九、隐私与合规声明

- **本地优先**：全流程本地 OCR，**不调用任何云端 API，聊天内容不出本机**，从根本上避免向第三方传输当事人信息。
- **无密钥面**：不依赖 API Key，仓库中不存在可泄露的凭证。
- **脱敏建议**：仓库示例一律使用合成虚构数据；真实截图请置于 `screenshots/` 或 `data/`（已被 `.gitignore` 忽略），切勿提交。
- **合法取证**：请确保获取聊天记录的方式符合相关法律规定，并注意固定原始载体。
- **仅供内部参考**：本工具生成的报告仅供律师内部办案参考，不构成法律意见；
  涉及法条提示须由承办律师核验现行有效性后引用；电子数据三性最终由人民法院依法认定。
